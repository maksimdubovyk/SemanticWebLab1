E2. Рік як рядок замість xsd:integer
==============================================================================
Помилково (рядки)          FILTER (?year > 2020) -> ['Amelie', 'Barbie', 'Dune', 'Tenet']
Виправлено (xsd:integer)   FILTER (?year > 2020) -> ['Barbie', 'Dune']
Причина: "2023" — рядок (xsd:string), тож числового порівняння немає. За специфікацією SPARQL
це помилка типу, а RDFLib впорядковує значення різних типів і вважає будь-який рядок
«більшим» за число — тому у вибірку потрапляють навіть Tenet (2020) та Amélie (2001).

E3. Літерал без мовного тегу не дорівнює літералу з тегом @en
==============================================================================
Помилково            SELECT ?film WHERE { ?film mo:hasGenre ?g . ?g rdfs:label "Science Fiction" . }
                     -> 0 рядків
Виправлено (@en)     SELECT ?film WHERE { ?film mo:hasGenre ?g . ?g rdfs:label "Science Fiction"@en . }
                     -> 7 рядків
Виправлено (STR())   SELECT ?film WHERE { ?film mo:hasGenre ?g . ?g rdfs:label ?l . FILTER (STR(?l) = "Science Fiction") }
                     -> 7 рядків

==============================================================================
E4. Wikidata: одиниці вимірювання тривалості (P2047)
==============================================================================
Помилково (wdt:P2047)        -> [('Inception', '148'), ('Oppenheimer', '10809')]
Виправлено (psn:P2047 / 60)  -> [('Inception', '148'), ('Oppenheimer', '180')]
Причина: wdt: повертає лише число «як введено»; для Oppenheimer одне з тверджень записане в секундах (10809 s), тож без урахування одиниць отримуємо хибне значення.
